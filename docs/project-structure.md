# Project Structure

MoonPost is organized as a MoonBit module with package directories at the
repository root. A directory with `moon.pkg` is a MoonBit package boundary, so
these package directories should stay stable unless the package import paths are
intentionally changed.

## Package Layers

The dependency direction should stay simple:

```text
timecode
subtitle
  ↑
qc ───────┐
retime ───┤
align ────┤
delivery ─┘
  ↑
cli
  ↑
cmd/main
```

- `timecode` and `subtitle` are foundational.
- `qc`, `retime`, and `align` build on those foundations.
- `delivery` composes subtitle/timecode/QC concepts for package preflight work.
- `cli` should describe command data, not perform filesystem work.
- `cmd/main` owns filesystem I/O, process exit codes, and command execution.
- `wasm_demo/core` exports a small browser-facing API and should avoid native
  filesystem dependencies.

## Naming Notes

- `wasm_demo/core` uses an underscore because it is a MoonBit package path.
- `wasm-demo` uses a hyphen because it is not a MoonBit package; it is the
  browser demo shell.
- `pkg.generated.mbti` files are generated by `moon info` and should be kept in
  sync with public API changes.
- Files inside a MoonBit package are organizational only. Moving declarations
  between files in the same package is safe when names and visibility stay the
  same, but moving directories changes package import paths.
